# دليل مدير النظام لربط Firebase — دائرة الاتصالات

هذا الدليل مخصص لمالك مشروع Firebase أو مديره التقني. لا يحتاج مدير النظام إلى إدخال مفاتيح سرية داخل التطبيق أو إرسالها عبر المحادثة.

## ما الذي سيحتاجه المدير؟

- حساب Google الذي سيُمنح صلاحية مدير النظام.
- صلاحية Owner أو Editor مناسبة على مشروع Firebase لإنشاء الإعدادات ونشر قواعد Firestore.
- نسخة المشروع من فرع `security/firebase-rules-bootstrap`.
- Flutter SDK وFlutterFire CLI وFirebase CLI على جهاز الإعداد.

> عنوان المدير يجب أن يُؤكد من صاحب المشروع قبل إضافته. لا تعتمد على عنوان البريد المكتوب في هذا المثال أو على إعداد محلي في جهاز المستخدم.

## المرحلة الأولى: إنشاء مشروع Firebase وربط التطبيقات

1. افتح [Firebase Console](https://console.firebase.google.com/) وأنشئ مشروعاً جديداً أو اختر المشروع المعتمد.
2. من صفحة المشروع، سجّل تطبيق Android باستخدام `applicationId` الفعلي الموجود في `android/app/build.gradle` أو `android/app/build.gradle.kts`.
3. سجّل تطبيق Web من إعدادات المشروع.
4. سجّل تطبيق iOS لاحقاً عند توفر بيئة macOS وXcode، مع استخدام Bundle ID الصحيح.
5. افتح **Authentication → Sign-in method** وفعّل **Google**، وحدد بريد دعم المشروع عند طلبه.
6. افتح **Firestore Database** وأنشئ قاعدة البيانات في الموقع الجغرافي المعتمد. لا تستخدم قواعد الاختبار المفتوحة.

## المرحلة الثانية: توليد إعدادات FlutterFire

من جذر المستودع وعلى جهاز المطوّر:

```bash
flutter pub get
dart pub global activate flutterfire_cli
firebase login
flutterfire configure
```

- اختر مشروع Firebase الصحيح.
- اختر Android وWeb، وأضف iOS عند توفر متطلباته.
- راجع الملف الناتج `lib/firebase_options.dart` وتأكد من عدم وجود قيم placeholder مثل `YOUR_API_KEY` أو `YOUR_PROJECT_ID`.
- لا ترفع مفاتيح Admin SDK أو ملفات Service Account إلى GitHub أو إلى تطبيق Flutter.
- ملف إعدادات Firebase العميلية ليس بديلاً عن قواعد Firestore؛ الحماية الفعلية يجب أن تكون في القواعد والخادم.

## المرحلة الثالثة: تهيئة مدير النظام لأول مرة

يجب أن ينفذ مالك المشروع هذه الخطوة يدوياً من Firebase Console قبل أول تسجيل دخول ناجح:

1. افتح **Firestore Database → Data**.
2. أنشئ Collection باسم `system_settings`.
3. أنشئ Document بمعرّف `telecom`.
4. أضف الحقول التالية:

| Field | Type | Value |
|---|---|---|
| `adminEmails` | array | بريد Google المعتمد للمدير، كنص داخل القائمة |
| `departmentName` | string | `دائرة الاتصالات` |
| `updatedAt` | string | تاريخ ووقت التهيئة بصيغة ISO 8601 |

مثال توضيحي للقيمة:

```json
{
  "adminEmails": ["ADMIN_GOOGLE_EMAIL"],
  "departmentName": "دائرة الاتصالات",
  "updatedAt": "2026-11-11T00:00:00Z"
}
```

استبدل `ADMIN_GOOGLE_EMAIL` بالبريد الذي أكّده مالك المشروع. يجب أن يكون هو البريد نفسه الذي سيستخدمه المدير في **Google Sign-In**.

**تنبيه:** وفق القواعد الحالية، يستطيع المستخدم المسجل قراءة وثيقة الإعدادات، ولذلك فإن عناوين المديرين الموجودة في `adminEmails` ليست بيانات سرية. لا تضع في هذه الوثيقة كلمات مرور أو مفاتيح أو رموز وصول. إذا كانت سرية قائمة المديرين مطلوبة، ينبغي نقل قرار الصلاحية إلى Custom Claims أو خدمة خلفية موثوقة قبل الإنتاج.

## المرحلة الرابعة: نشر قواعد Firestore

من جذر المستودع، وبعد مراجعة `firestore.rules`:

```bash
firebase use YOUR_FIREBASE_PROJECT_ID
firebase deploy --only firestore:rules
```

استبدل `YOUR_FIREBASE_PROJECT_ID` بمعرّف المشروع الفعلي. راجع أن Firebase CLI يشير إلى المشروع الصحيح قبل النشر.

لا تنشر القواعد قبل اختبارها بحساب مدير وحساب مستخدم عادي. القواعد الحالية تمنح جميع المستخدمين المسجلين قراءة بيانات `department_data/telecom`، بينما تقتصر الكتابة على المدير؛ راجع هذا النطاق إذا كانت بيانات بعض الأقسام تتطلب خصوصية مختلفة.

## المرحلة الخامسة: اختبار المدير والمستخدم

1. سجّل الدخول بالبريد المدرج في `adminEmails`.
2. تحقق من أن التطبيق حمّل إعدادات النظام وأن واجهة المدير تعرض صلاحيات الإدارة.
3. سجّل الخروج، ثم سجّل الدخول بحساب مستخدم عادي.
4. تحقق من أن المستخدم العادي لا يستطيع الكتابة مباشرة إلى بيانات القسم، وأن طلباته تظهر له فقط.
5. اختبر إرسال طلب اعتماد، ثم اعتماده أو رفضه من حساب المدير.
6. اختبر قراءة البيانات وتسجيل سجل التدقيق.
7. بعد تغيير قائمة المديرين من Console، اطلب من الحساب المتأثر تسجيل الخروج والدخول مجدداً لإعادة تحميل القائمة.

## ما لا يستطيع المدير إنجازه من داخل واجهة التطبيق حالياً

- إنشاء مشروع Firebase أو ربطه تلقائياً دون إعداد FlutterFire على بيئة بناء.
- نشر قواعد Firestore دون Firebase CLI وصلاحية مناسبة.
- إنشاء أول وثيقة مدير من داخل التطبيق؛ هذا محظور عمداً في القواعد.
- استخدام مفاتيح Admin SDK داخل تطبيق Flutter.
