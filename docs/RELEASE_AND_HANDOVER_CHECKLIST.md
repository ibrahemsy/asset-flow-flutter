## 3. نطاق النقل والتحقق

### قاعدة البيانات
- جرد المخططات والجداول والأعمدة والقيود والفهارس والعروض والدوال والمشغلات والامتدادات والمنح وسياسات RLS.
- نقل مخطط التطبيق وبياناته مع الحفاظ على المفاتيح والعلاقات.
- لا تنسخ مخططات Supabase الداخلية `auth` أو `storage` باستخدام استيراد SQL عام؛ اتبع مسار Supabase الرسمي المدعوم لكل خدمة.
- قارن أعداد السجلات وقيماً مرجعية/بصمات للبيانات بعد النقل.
- اختبر سياسات RLS بحساب مدير وحساب مستخدم عادي وحساب غير مخصص.

### Auth
- لا تنسخ password hashes أو refresh tokens أو أسرار JWT.
- أنشئ/ادعُ المستخدمين في المشروع الوجهة عبر واجهات Auth الإدارية المدعومة، ثم أعد ربط معرفات المستخدمين بأدوار التطبيق.
- خطط لإعادة تعيين كلمات المرور وإعادة ربط موفري OAuth/SSO عند الحاجة.
- لا تمنح أي مستخدم دور مدير اعتماداً على البريد أو user_metadata وحدهما.

### Storage
- انقل تعريفات الحاويات وإعداداتها وسياسات الوصول، ثم الملفات الفعلية باستخدام آلية النقل الموصى بها من Supabase.
- تحقق من عدد الملفات وأحجامها وإمكانية تنزيل عينات خاصة وعامة وفق إعداداتها.
- تذكّر أن بيانات metadata للملفات ومحتوى الملفات الفعلي مساران يجب التحقق منهما معاً.

### إعدادات المشروع
- أعد تكوين مفاتيح Edge Functions وOAuth وSMTP وredirect URLs وwebhooks وCORS وإعدادات Auth على الوجهة بشكل منفصل.
- لا تنقل أسرار المشروع القديم إلى تطبيق العميل.
- حدّث إعدادات النشر والنسخ الاحتياطي والمراقبة.

## 4. اختبار القبول قبل التحويل

- تسجيل دخول المدير الجديد وتحديث كلمة المرور.
- التحقق من الدور عبر RPC وقواعد RLS.
- إنشاء/تعديل/قراءة/حذف جهاز وبطاقة عهدة وحركة وبلاغ صيانة.
- إنشاء سويتش ومنافذه وربط جهاز بمنفذ، ثم اختبار منع التكرار.
- اختبار سجل التدقيق والطلبات المعلقة والتصدير إلى Excel.
- اختبار قارئ USB والكاميرا على Android ومتصفح مدعوم.
- اختبار الويب على استضافة HTTPS.
- اختبار استعادة نسخة احتياطية من المشروع الوجهة.

## 5. التحويل الآمن

1. إيقاف الكتابات مؤقتاً أو تحديد نافذة تجميد تغييرات واضحة.
2. تنفيذ النسخة النهائية المتزامنة من البيانات.
3. إعادة مقارنة الأعداد والبصمات.
4. موافقة المدير الحالي والمدير الجديد على تقرير التحقق.
5. تحويل إعدادات التطبيق إلى المشروع الوجهة.
6. مراقبة تسجيل الدخول والعمليات وسجلات الأخطاء.
7. بعد ثبات الوجهة فقط، تغيير تعيين المدير الأساسي وسحب صلاحية المدير السابق.
8. إبقاء المشروع المصدر ونسخته الاحتياطية دون حذف خلال فترة رجوع متفق عليها.

## 6. متطلبات النشر

- Android: إنشاء keystore يملكه مالك المشروع، تخزينه كـ GitHub Actions secrets، ثم بناء APK/AAB موقّع واختبار تثبيته.
- iOS: Apple Developer Team وشهادة توزيع وProvisioning Profile، ثم بناء IPA موقّع واختباره عبر TestFlight.
- Supabase Auth: تفعيل Leaked Password Protection من إعدادات Password Security.
- إجراء اختبار قبول وظيفي وأمني وتوثيق نتيجة كل منصة قبل وصف النسخة بأنها إنتاجية.
